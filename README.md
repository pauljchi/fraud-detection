# Credit Card Fraud Detection 

As long as digital payment systems have existed, so has fraud. Financial institutions need to have systems in place to process transactions rapidly while identifying as many fraudulent transactions as possible. Failing to detect fraudulent transactions can cause problems for payment system users and lead to costly investigations and chargebacks. On the other hand, flagging too many legitimate transactions as fraudulent can cause considerable frustration. Moreover, most financial transactions are legitimate. A model that guesses "no fraud" every time will be highly accurate, but useless. Class imbalance is one of the major challenges in fraud detection.  

This project investigates several ways a practitioner might deal with the problem of imbalanced classes within a dataset containing credit card transactions by European cardholders. It compares several statistical and machine learning approaches, evaluating their ability to rank fraud cases. The project serves as a case study rather than a deployment recommendation: the dataset covers only about two days in 2013, and most predictors are anonymized. 

## Data and analytical sample

The source dataset contains 284,807 transactions made by European cardholders over approximately two days in September 2013. Only 492 transactions are labeled as fraud, representing a prevalence of about 0.173 percent. The data is available from the [Machine Learning Group at Université Libre de Bruxelles](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud).

Each row includes elapsed transaction time, transaction amount, a fraud label, and 28 anonymized variables named `V1` through `V28`. Those variables are principal components: statistically constructed combinations of the original transaction characteristics. This transformation helps protect confidential information and reduce redundancy among the predictors, but it also prevents real-world interpretation. For example, the variable `V14` might be useful for prediction, but it cannot be interpreted as customer behavior, merchant risk, or any other such characteristic. 

Initial exploratory analysis found no missing values, negative times, or negative transaction amounts. It also identified 1,081 exact row repetitions beyond the first occurrence of each. These repetitions were treated as duplicate records and were removed during data cleaning. Because the released data do not contain transaction identifiers, treating exact row repetitions as duplicates is a cleaning assumption rather than a confirmed correction. After the duplicates were removed, the dataset had 283,726 transactions and 473 labeled frauds. 

In the cleaned dataset, fraudulent transactions had a mean of 123.87 units, compared with 88.41 units for legitimate transactions. Fraudulent transactions also had a lower median of 9.82 units, compared with 22.00 units for legitimate transactions. The distributions are highly skewed, and fraud prevalence is higher in both the lowest and highest amount ranges than in the middle of the distribution. Fraud rates also vary across the 48-hour sample. Although some time intervals contain very few fraud observations, this is more likely to reflect variation than a durable time-of-day pattern. Transactions spanning a longer period would be needed to investigate time-related patterns. 

## How the models were compared

The cleaned dataset is divided into an 80 percent training set and a 20 percent test set while preserving approximately the same fraud rate in each. The test set contains 56,746 transactions, including 95 fraudulent transactions. It is not used to fit the models, select among the candidate models, or determine the maximum-F1 reference cutoff. 

Four approaches are evaluated. A dummy classifier provides a minimum performance benchmark. Weighted logistic regression estimates a linear relationship while giving the rare fraud observations greater influence during training. A second logistic regression uses SMOTE, a procedure that creates synthetic minority-class examples from the training data rather than simply duplicating existing fraud observations. Finally, weighted XGBoost uses many decision trees to model nonlinear relationships while placing additional weight on the rare class. 

The models are compared using five-fold cross-validation. The training data are divided into five parts. Each model is fitted on four of those parts and evaluated on the fifth. This process is repeated until every training observation has been evaluated by a model that was not fitted on that observation. The out-of-fold scores provide a more realistic indication of how each model may perform on new transactions because every score is generated by a model that was not trained on that observation. To prevent data leakage, scaling and SMOTE occur separately within each training fold. 

The primary metric for comparison is Average Precision. It evaluates how well a model places fraudulent transactions near the top of its risk ranking while limiting false positives. Higher Average Precision values indicate better performance. As expected, the dummy classifier has an Average Precision close to the fraud prevalence. 

| Candidate model | Mean cross-validation Average Precision |
|---|---:|
| Dummy classifier | 0.002 |
| Weighted logistic regression | 0.738 |
| SMOTE logistic regression | 0.755 |
| Weighted XGBoost | 0.843 |

Among these candidates, weighted XGBoost produces the highest mean cross-validation Average Precision, at 0.843. After being fitted on the training set, weighted XGBoost achieves Average Precision of 0.812 on the test set. 

## Interpreting the model's fraud scores

The selected model assigns each transaction a number between zero and one. This fraud score is used to rank transactions, not to estimate the probability of fraud. The scores are then compared with a cutoff threshold to determine whether a transaction is flagged for review. Being flagged does not necessarily mean that a transaction is fraudulent. 

For example, a score of 0.959 does not mean that the transaction has a 95.9 percent probability of being fraudulent. It means that the transaction receives a sufficiently high score under this fitted model to exceed that particular cutoff. Producing interpretable probabilities would require additional calibration steps that were not explored in this project. 

## From scores to review decisions

The model ranks transactions from highest to lowest risk, but the institution must decide how far down that ranking to investigate. That decision depends on staffing capacity, the cost of reviewing an alert, the losses from missed fraud, and the burden placed on customers when legitimate transactions are flagged. 

For that reason, this analysis cannot identify a single optimal cutoff. The cutoff that maximizes F1 on the out-of-fold training scores is included as a benchmark. It identifies a favorable combination of precision and recall, but it does not account for the relative economic costs of false positives and false negatives. 

Several example review policies are shown in the table below. For each review policy, the highest-scoring transactions are sent for review, and the table reports the resulting outcomes on the test set. 

| Review policy | Alerts | Actual alerts per 10,000 | Precision | Fraud capture | Frauds found | False alerts | Frauds missed |
|---|---:|---:|---:|---:|---:|---:|---:|
| Review top 5 per 10,000 | 28 | 4.9 | 100.0% | 29.5% | 28 | 0 | 67 |
| Review top 10 per 10,000 | 56 | 9.9 | 98.2% | 57.9% | 55 | 1 | 40 |
| Maximum-F1 reference | 78 | 13.7 | 91.0% | 74.7% | 71 | 7 | 24 |
| Review top 20 per 10,000 | 113 | 19.9 | 68.1% | 81.1% | 77 | 36 | 18 |
| Review top 50 per 10,000 | 283 | 49.9 | 28.3% | 84.2% | 80 | 203 | 15 |

The incremental trade-offs are also informative. Increasing capacity from 10 to 20 reviews per 10,000 transactions identifies 22 additional frauds and produces 35 additional false alerts. Within this test sample, expanding the review rate shows diminishing returns. 

At the maximum-F1 reference cutoff, the model sends 78 of 56,746 transactions for review, equivalent to 13.7 alerts per 10,000 transactions. It identifies 71 of the 95 labeled frauds, produces seven false alerts, and misses 24 frauds. This maximum-F1 reference is merely an illustrative example. It is not intended as a recommended policy. 


## Scope and limitations

The model successfully places many of the labeled frauds near the top of its risk ranking within this dataset. The results do not establish that the same performance would persist over time or generalize to another financial institution. 

The test set contains only 95 fraud cases, so the reported metrics remain subject to sampling variation. Reclassifying even a small number of transactions could meaningfully change the reported rates. In addition, the training and test observations were randomly drawn from the same two-day period in 2013. Payment systems and fraud characteristics may have changed substantially since then. A stronger study would use newer data covering a much longer period. 

The anonymized variables further limit the conclusions that can be drawn. Model diagnostics identify `V4`, `V14`, `V11`, and `V12` as especially useful for prediction. These importance measures describe predictive relationships within the fitted model. They do not show that the variables cause fraud. Without the relevant cardholder, merchant, and demographic information, this analysis cannot provide insights into real-world impacts.

Download the source data and save it as `data/creditcard.csv`. Then run the two notebooks in sequence, starting each from a clean kernel so that no results depend on variables left over from an earlier session. 

[`01_data_preparation_eda.ipynb`](01_data_preparation_eda.ipynb) checks the data, documents the cleaning decisions, and conducts exploratory analysis. The notebooks use Python with NumPy, pandas, Matplotlib, seaborn, scikit-learn, imbalanced-learn, and XGBoost. Both notebooks have been executed sequentially using clean kernels and retain their outputs so that the complete analytical record can be reviewed without rerunning the code.

## Conclusion

Among the four models evaluated, weighted XGBoost was the most effective at placing fraudulent transactions near the top of the ranking and performed well on the test data. The results also show an important trade-off: reviewing more transactions detects additional fraud, but beyond a certain point, doing so adds many more legitimate transactions than fraud cases to the review queue. Finding the right balance requires care.  

Newer data and a longer observation period would make it possible to study changes in fraud over time. Carefully protected customer and merchant identifiers could also help identify repeated behavior and evaluate whether the model performs consistently across groups. Before operational use, an institution would also need to consider the number of transactions that investigators can review, the losses associated with missed fraud, and the cost of false alerts. Together with model performance, these considerations would determine the appropriate transaction review policy.
